# Linode 开机面板

一个用 Go 实现的单二进制 Web 面板，用于管理你的 Linode 实例：查看列表、开机、关机、重启，并在开机后自动轮询直到实例运行，给出可用的 SSH 连接信息。此外还支持「删机重建」：删除实例并用相同 region/type/image 重建，然后在重建后的实例上通过 SSH 执行该实例配置的开机脚本；创建新实例时填写的开机脚本也会在实例启动后自动执行。

## 功能

- 多用户登录：每个用户拥有独立的权限组与多个 Linode PAT
- **账号管理**：绑定/管理自己的 Linode PAT（账号），并用某个账号创建新实例（名称 + 地区 + 机型 + 镜像）；**每个账号可绑定一个执行 Agent**，使「经 Agent 执行」的操作固定由该 Agent 完成
- **Agent 执行**：面板可把开机/关机/重启/删机重建下发到已注册的 Agent 执行；**面板自身也可作为 Agent**（`--self-agent`，默认开启），无需单独运行 Agent 进程即可使用经 Agent 流程
- 权限控制：`view` / `power` / `rebuild` / `script` / `admin` 五档权限
- 列出账号下的 Linode 实例（名称、状态、地区、型号、镜像、公网 IP、标签）
- 一键开机 / 关机 / 重启
- 开机后自动轮询实例状态，运行后给出 SSH 命令并探测端口连通性
- 查看账号下已保存的 SSH 公钥
- **删机重建**：删除旧实例并以相同 region/type/image 重建，重建后可自动执行保存的开机脚本
- **开机脚本**：**每个实例可配置独立的开机脚本**；创建实例时填写的脚本会在实例启动后由面板通过 SSH 以 root 身份自动执行，重建完成后再次执行（未配置的实例重建时使用内置默认模板）
- **默认开放所有端口**：创建实例或删机重建后，面板自动把「允许全部入站/出站流量」的 Linode Cloud Firewall 绑定到该实例，使任意开机方式下所有端口都放行
- **被墙后自动换 IP**：可为单个实例开启监测，从国内探测其端口；连续失败达到阈值后自动删机重建，换到新的公网 IP（重建后配置自动跟随新实例）
- **账号组自动替换**：把多个账号绑定成一个命名组；组内某账号被封号或余额不足时，自动用**相同配置**在组内另一个可用账号上重建替换实例，保持服务不中断

## 首次启动与登录

首次运行（数据库文件不存在）时，面板会初始化内置权限组并创建一个默认管理员账号 `admin`，其密码为**随机生成**并在启动日志中打印：

```text
msg=... 初始管理员账号：admin / 密码：<随机>（请尽快登录修改）
```

请立即用该账号登录并修改密码。后续启动不再打印密码；若遗忘密码，删除数据库文件后重新启动即可重新生成（**注意**：这会清除所有用户、PAT 与各实例的开机脚本、root 密码）。

启动后打开 <http://127.0.0.1:8787>，输入用户名与密码登录。

## 用户与权限

### 权限组

每个用户属于一个权限组，组定义了一组权限。内置组（管理员 / 只读 / 运维）在首次启动时创建，可在 Web UI 中增删改。权限矩阵：

| 权限 | 说明 |
| ---- | ---- |
| `view` | 查看实例列表、状态与 SSH 信息 |
| `power` | 开机 / 关机 / 重启 |
| `rebuild` | 删机重建与查看重建任务 |
| `script` | 读取与保存每个实例的开机脚本 |
| `admin` | 用户与权限组管理 |

### Linode PAT

每个用户可绑定多个 Linode Personal Access Token（PAT）。面板对实例的读取与操作都使用**当前登录用户自己的 PAT**，互不干扰；同一用户绑定多个 PAT 时列表会聚合所有实例，单个 PAT 失败不会拖垮整体。

在「账号管理」页面中每个用户可为**自己**绑定多个 PAT 并命名；管理员也可以在「用户管理」中为任意用户添加 PAT。绑定时勾选以下 scope：

- `linodes:read_write`（列出与操作实例）
- `account:read_only`（读取 SSH 公钥）
- `firewall:read_write`（读取/创建/绑定 Cloud Firewall，用于「默认开放所有端口」）

Token 只以**尾 4 位**形式显示（如 `****c3d9`），完整 PAT 仅在添加时输入一次，之后不会回显。

在「账号管理」页面中每个账号可**绑定一个执行 Agent**（下拉框选择）：绑定后，对该账号实例执行的「经 Agent」操作（开机/关机/重启/删机重建）会固定路由到该 Agent，而不是默认的面板自身；未绑定则沿用默认行为（面板自身的「本地面板」Agent）。绑定仅影响经 Agent 的执行路径，不影响面板直发。

> **面板自身作为 Agent**：默认（`--self-agent`）面板会在启动时把自己注册为一个名为「本地面板」的 Agent，出现在 Agent 列表中（标记为「本地」，不可删除，但可在「Agent 管理」页**重命名**，新名称持久化，重启后仍生效；重命名持久化后，仅当启动时显式传 `--self-agent-name` 才会覆盖）。这样即使没有单独的 Agent 进程，「经 Agent 执行」的操作也会由面板进程直接执行（复用面板自己的 Linode 客户端与重建任务）。**使用本地面板无需设置注册码**——面板搭建后即可直接经 Agent 执行；远程 Agent 仍需注册码。路由优先级为：操作中显式选择的 Agent → 账号绑定的 Agent → 本地面板 → 第一个已注册 Agent（仅在 `--self-agent=false` 时生效）。可通过 `--self-agent=false` 关闭。

> **Agent 重命名**：在「Agent 管理」页可重命名**本地面板 Agent**（标记「本地」）以及**页面手动新增的 Agent**（「新增 Agent」按钮创建，标记「手动」）。本地面板 Agent 的新名称持久化保存，重启后仍生效；手动 Agent 的名称即时生效（该 Agent 记录本身为内存态）。通过注册码自助注册的远程 Agent 不可重命名——其名称由 Agent 进程在注册时上报。

## 命令行参数

| flag        | 默认值                               | 说明                                            |
| ----------- | ------------------------------------ | ----------------------------------------------- |
| `--addr`    | `127.0.0.1:8787`                     | HTTP 监听地址                                   |
| `--api-base`| 环境变量 `LINODE_API_BASE`，否则 `https://api.linode.com/v4` | Linode API v4 基础地址，一般无需修改 |
| `--ssh-port`| `22`                                 | SSH 端口，用于生成的 `ssh` 命令与连通性探测      |
| `--state`   | `~/.config/linode-panel/state.db`  | SQLite 数据库路径（用户、PAT、实例开机脚本与 root 密码）          |
| `--self-agent` | `true`                           | 面板自身是否作为 agent：注册一个「本地面板」agent，使经 agent 操作可由面板进程直接执行（`--self-agent=false` 关闭） |
| `--self-agent-name` | `本地面板`               | 本地面板 agent 的名称；未指定该参数时沿用「管理后台 → Agent 管理」中重命名后的持久化名称（见上） |
| `--auto-rebuild` | `true`                          | 是否启用「被墙后自动删机重建换 IP」后台监测（`--auto-rebuild=false` 关闭） |
| `--auto-rebuild-tick` | `1m`                       | 监测轮询间隔；每个实例仍按自身配置的检测间隔被实际探测 |
| `--auto-rebuild-check-api` | 环境变量 `AUTO_REBUILD_CHECK_API`，否则 `https://api.24kplus.com/ipcheck` | 国内 IP 连通性探测接口（被墙判定用） |

例如修改监听地址与 SSH 端口：

```bash
go run . --addr 0.0.0.0:8787 --ssh-port 2222
```

环境变量：

- `LINODE_API_BASE`：可选，覆盖 Linode API 基础地址。

> **迁移说明**：旧版本通过环境变量 `LINODE_TOKEN` 注入单个全局 Token，该变量**已移除**。现在 Token 改由用户在 Web UI 中按账号绑定，请先在「用户管理」中为各用户添加 PAT。

## 数据库

SQLite 数据库（默认 `~/.config/linode-panel/state.db`，由 `--state` 指定）持久化用户、密码哈希（bcrypt）、权限组、各用户的 PAT、注册码、各实例的开机脚本与 root 密码。数据库文件权限为 `0600`（仅当前用户可读写）。请妥善保管，切勿提交到版本库或泄露给他人。root 密码为重置/重建新实例所需，当前以明文保存在该数据库中，请像保护 PAT 一样保护数据库文件。

> **实例缓存**：每次成功从 Linode API 拉取实例列表后，面板会把该账号（PAT）的实例快照缓存到数据库中。**默认（进入页面、自动加载）直接读缓存、不请求 Linode API**；实例在页面中按账号分组展示，只有点击**账号分组行上的「刷新」按钮**才会重新请求 Linode API 获取**该账号下全部实例**的最新数据并更新缓存。当某次拉取失败时，用该账号上次缓存的快照回退展示，并在对应实例行提示「显示缓存数据」。开机/关机/重启/创建/重建等变更操作会把该账号的缓存标记为过期，下一次列表自动重新拉取最新状态。

> **不存在实例的保留与迁移**：刷新时若某实例在 Linode 上游已不存在（404），面板**不会删除**该缓存行，而是把它标记为「不可用」并继续显示。行内提供「迁移」按钮：选择另一个账号后，面板用缓存中的地区/机型/镜像/名称以及已保存的开机脚本、root 密码在该账号上创建一个新实例，并把这条稳定缓存行（连同脚本、root 密码、自动换 IP、替换配置）迁移到新账号的新实例。迁移需要面板能直接访问 Linode API（不经 Agent）；若缓存中未保存 root 密码，迁移时需手动填写。不可用实例也可用「删除记录」只清理面板缓存及其配置，不影响任何运行中的实例。

> **稳定实例标识**：`instance_cache` 表以自增 `id` 作为面板内的稳定实例标识，`instance_id` 是当前的 Linode 实例 ID。删机重建只更新该行的 `instance_id`（新实例 ID），行的 `id` 保持不变，因此按实例保存的开机脚本、自动换 IP、账号组替换配置会自动继承到新实例，无需手工迁移。

> **迁移说明**：旧版本使用 JSON 状态文件（`state.json`）。本次改动不自动迁移旧数据，请自行确认是否需要保留。新的数据库文件默认使用 `.db` 后缀。

## SSH 说明

- 面板生成 SSH 命令时固定使用 `root` 用户（可在创建实例时通过「SSH Key」功能注入你的公钥）。
- 优先使用公网 IPv4；若实例没有公网 IPv4，则回退到 SLAAC IPv6 地址。
- SSH 端口非 22 时，生成形如 `ssh -p 2222 root@<ip>` 的命令，端口由 `--ssh-port` 指定。
- 面板会尝试连接 SSH 端口（3 秒超时）以显示「可连接 / 不可连接」状态；该探测仅针对运行中的实例。

## 默认开放所有端口

面板在**创建新实例**（含账号组自动替换）完成后，会自动把名为 `linode-panel-allow-all`（标签 `linode-panel-allow-all`）的 Cloud Firewall 绑定到该实例。该防火墙的入站与出站规则放行全部 TCP/UDP/ICMP 流量（地址 `0.0.0.0/0` 与 `::/0`），因此无论实例以何种方式开机，所有端口都会放行。

行为说明：

- 防火墙**按 region 复用**：同一账号同一地区只创建一份「允许全部」防火墙，后续实例直接绑定；不同地区各自创建一份。
- 绑定是**幂等**的：实例已绑定则跳过，不会重复绑定。
- 该步骤为**尽力而为**：若当前 PAT 缺少 `firewall:read_write` scope 或实例尚未就绪，会记录警告但不阻塞创建/替换。要保证生效，请给 PAT 勾选 `firewall:read_write`。
- 仅对**此后**通过面板创建/替换的实例自动生效；**删机重建**不会绑定该防火墙，**已存在**或重建后的实例可到 [Linode Cloud Manager](https://cloud.linode.com) 手动绑定。
- 该防火墙允许所有入站流量（含暴露公网端口）。如需收紧，请在 Cloud Manager 中修改规则或从实例解绑。

## 删机重建与开机脚本

重建是**破坏性**操作：面板会先关闭并删除旧实例（释放其临时 IP），然后用相同的 region/type/image 创建一个全新实例。**磁盘和系统内的数据会丢失**；但面板侧按实例保存的配置（开机脚本、root 密码、自动换 IP、账号组替换）以及实例的标签会自动继承到新实例。面板为每个实例保留一个稳定的内部标识（`instance_cache` 表的自增 `id`）：重建只把该标识关联的 Linode 实例 ID 更新为新实例 ID，因此配置无需迁移即可跟随。

**root 密码**：通过面板创建的实例会自动保存创建时填写的 root 密码，重建时用同一密码创建新实例。旧实例若没有保存过密码，可在「编辑 → root 密码」中设置，或直接在重建弹窗中填写（填写后会保存为该实例配置）。未保存密码时，新实例只注入一次性 SSH 密钥，没有可用的密码登录。经 Agent 执行重建时，该密码会随重建命令一并下发到对应 Agent。

重建流程（失败即停，每步状态与日志可在任务详情中查看）：

1. 关闭旧实例
2. 删除旧实例
3. 以相同 region/type/image（并保留原名称与标签）创建新实例（默认开机），并注入一次性 SSH 公钥
4. 轮询等待新实例运行（每 3 秒，最长 10 分钟）
5. 通过 SSH 在实例上以 root 身份执行该实例配置的开机脚本（超时 5 分钟）
6. 探测 SSH 端口，成功才标记任务完成

### 开机脚本

开机脚本**按实例独立配置**，保存在 `--state` 指定的 SQLite 数据库中（默认 `~/.config/linode-panel/state.db`），修改后立即写入磁盘。脚本以 `bash -s` 方式、root 用户执行；**请只保存你信任的内容**，因为它在创建后与重建后的实例上都会以 root 权限运行。

每个实例都可以配置**独立的开机脚本**：

- 在实例列表的「编辑」弹窗中为单个实例编辑脚本；已配置自定义脚本的实例按钮会带 `•` 标记。
- **创建实例**时可在弹窗底部填写「开机脚本（可选）」；创建请求立即返回，面板在实例启动后通过 SSH 自动执行该脚本，同时把它保存为该实例配置（之后重建也会执行）。留空则不执行脚本。
- 创建时的脚本执行在**后台**进行；执行状态（等待启动 / 执行中 / 成功 / 失败及错误信息）会显示在该实例的「编辑」弹窗中。该状态保存在内存里，面板重启后清空。
- 重建实例时，弹窗预填**该实例自己的脚本**（未配置时预填内置默认模板），确认重建后该内容保存为该实例的配置。
- 未配置脚本的实例在重建时使用内置默认模板；「恢复默认」可取消某实例的自定义配置。
- 脚本生效顺序：**请求脚本 → 实例已配置脚本 → 内置默认模板**。

内置默认脚本模板：

```bash
#!/usr/bin/env bash
# Linode 开机脚本（重建后自动执行）
set -euo pipefail
# 示例：更换 SSH 端口
# sed -i 's/^#Port 22/Port 2222/' /etc/ssh/sshd_config && systemctl restart sshd
```

### 安全提示

- 用于连接新实例（创建时执行脚本、删机重建）的 SSH 私钥只在内存中生成和使用，结束后即丢弃，**不会**写入磁盘或发送到浏览器。
- 开机脚本以 root 身份在新实例上执行，请只放入可信命令。
- 重建会删除旧实例及其磁盘，操作前请确认你已经备份了必要数据。

## 被墙后自动重建换 IP

面板可以为**单个实例**开启「被墙后自动删机重建换 IP」：后台监测会定期从国内探测该实例的公网 IPv4 与指定端口，连续失败达到阈值后自动触发一次「删机重建」，让实例换到新的公网 IP。它与独立的 `aws_auto_changeip` 工具思路类似，但这里直接调用 Linode API 重建，而不是操作机器人。

### 开启方式

在实例行的操作列点击 **「自动换IP」**，在弹窗中：

- 勾选「被墙后自动删机重建换 IP」；
- **检测端口（TCP）**：国内探测的目标端口，默认 `--ssh-port`（22）；
- **连续失败多少次判定被墙**：默认 3，范围 1-20；
- **检测间隔（分钟）**：同一实例两次探测的最小间隔，默认 5 分钟；
- 保存后可点「立即检测」查看当前状态。

开启后该实例行的按钮会显示 `自动换IP •` 标记。

### 判定与重建流程

1. 面板每 `--auto-rebuild-tick`（默认 1 分钟）扫描一次已开启的实例；只有距上次检测已超过实例自身「检测间隔」的实例才会真正探测，避免频繁请求。
2. 探测前先读取实例状态：**只有运行中（running）且有公网 IPv4 的实例才会被探测**，关机/无公网 IP 时记为「未检测」并跳过，避免把「关机」误判成「被墙」。
3. 通过 `--auto-rebuild-check-api`（默认 24kplus 的 ipcheck）从国内节点探测 `IP:端口`；仅以 **TCP 端口是否连通** 判定被墙（`ping` 状态只写入详情），接口自身出错不计入失败次数。
4. 连续失败达到阈值后，复用「删机重建」流程：关闭旧实例 → 删除 → 以相同 region/type/image（并保留原名称）重建 → 执行该实例配置的开机脚本（未配置则用内置默认模板）→ 探测 SSH 端口。
5. 重建成功后，面板会自动把自动换 IP 配置跟随到新实例：配置按实例的稳定缓存 id 保存，重建只更新该缓存行关联的 Linode 实例 ID，状态清零后继续监测。若重建失败，保留配置并在下一轮重试。

> **注意**：重建是破坏性操作，会删除旧实例的全部磁盘与数据。请先确认实例上没有需要保留的数据。
>
> 该监测由**面板进程**执行（需要面板侧能访问 Linode API 与探测接口），不经过账号绑定的 Agent。

### 状态说明

弹窗底部显示该实例的最新监测状态：

| 状态 | 含义 |
| ---- | ---- |
| 连通 | 最近一次探测端口可达 |
| 疑似被墙 | 探测端口不通，正在累计失败次数 |
| 重建换 IP 中 | 已触发重建，正在等待任务完成 |
| 检测出错 | 探测接口/读取实例失败（不计入失败次数） |
| 未检测（实例未运行） | 实例不在运行中或无公网 IPv4，已跳过 |

若实例被删除（例如在 Linode 控制台手动删除），监测会自动移除其配置。

权限：需要 `rebuild` 权限（与删机重建一致）。

## 账号组与自动替换

「账号组」把多个 Linode 账号（PAT）绑定成一个**命名集合**，用于在这些账号之间做故障转移：当组内某个账号被封号或余额不足时，面板会把它名下的实例逐个在组内另一个可用账号上以相同配置重建替换（同一时间只处理一个替换任务），尽量避免服务中断。它与「被墙后自动重建换 IP」互补——后者解决**单个实例的 IP 被墙**，前者解决**整个账号不可用**。

### 概念

- 账号组是一组 Linode 账号（PAT）的命名集合，名字由你自己指定，便于区分用途（例如「生产」「备用」）。
- **一个账号可以同时属于多个账号组**，不同组之间互不影响。
- 账号仍是「账号管理」中各用户绑定的 PAT；把账号加入组只是建立关联，不改变其权限归属。

### 目的

组内某个账号被封禁（账号不可用）或没有余额时，面板用**相同配置**在组内另一个账号上重建实例，使服务继续运行，而不是停在故障账号上等待人工处理。

### 触发条件

满足以下任一条件即视为该账号不可用，可触发替换：

| 条件 | 说明 |
| ---- | ---- |
| 账号被封禁 / 凭证失效 | 调用 Linode API 返回 `401` / `403`（视为立即不可用），说明 PAT 已失效或账号被限制 |
| 账号余额不足 | 账号存在欠款，或未出账金额达到**余额阈值**（判定余额不足的门槛） |

### 目标开机配置

从 T13 起，自动替换采用**严格模式**：触发替换时**不再读取旧实例的配置**，而是直接使用账号组预填的「目标开机配置」。

#### 配置项

在账号组卡片上点击「目标开机配置」可打开配置弹窗，填写以下字段：

> 弹窗顶部提供「从已有缓存实例填充」下拉框，选项来自实例列表缓存；选择某个实例后会自动回填 region / type / image / label，并回填该实例已配置的开机脚本（未配置时脚本保持为空）。回填后仍可手动修改。

| 字段 | 说明 |
| ---- | ---- |
| **region** | 目标开机区域，必填（如 `us-east`） |
| **type** | 目标机型，必填（如 `g6-standard-1`） |
| **image** | 目标镜像，必填（如 `linode/debian12`） |
| **label** | 目标实例名称，必填 |
| **script** | 开机脚本（可选，空则不写入脚本） |
| **booted** | 创建后是否自动开机（默认为 `true`） |

- **组未填写目标开机配置**时，即使达到失败阈值也不会触发替换，状态记为 `error`，详情为「未填写账号组目标开机配置」；需先在面板中填写组配置后再触发。
- 组配置与旧实例配置**完全解耦**：旧实例被替换后不再参与新实例配置的读取，新实例配置完全由组配置决定。

### 替换流程

1. 读取账号组预填的**目标开机配置**（region / type / image / label / script / booted）。
   - 若组未填写配置 → 状态 `error`，详情「未填写账号组目标开机配置」，**不触发替换**。
2. 在组内**另一个可用账号**上，用组配置创建新实例，并写入组配置里的开机脚本（若有）。
3. 迁移该实例的替换配置到新实例，避免替换后监测中断。
4. 记录替换状态（是否成功、原账号与新账号），供后续在面板中查看与排查。

> **注意**：替换通常在创建新实例后删除旧实例（因此仍是**破坏性**操作，请先确认实例上没有需要保留的数据）；但若故障账号凭证已失效、无法调用 Linode API 删除，旧实例可能继续运行，需人工确认后清理，面板不会假定其已消失。

### 配置项

- **失败阈值**：健康检查请求**连续失败（含网络错误）**达到该次数才判定账号不可用并触发替换，避免偶发请求失败造成误判；而 `401` / `403` 视为立即不可用，不受该阈值约束。
- **检测间隔**：两次账号健康检查之间的最小间隔。
- **余额阈值**：判定「余额不足」的门槛（余额/未出账金额），达到即视为余额不足。

具体默认值与可选范围以 Web UI 中的实际设置为准。

### 限制与注意

- **同一时间只允许一个重建替换任务进行**，避免并发重建互相干扰。
- **组内没有可用账号时不替换**，只记录告警，等待人工补充账号后处理。
- 替换需要面板侧能访问 Linode API；与「被墙后自动换 IP」一样，该流程由**面板进程**执行，不经过账号绑定的 Agent。

## 安全说明

- PAT 只保存在服务端 SQLite 数据库中（`0600`），按用户隔离，**绝不会**发送到浏览器；Web UI 仅展示尾 4 位。
- 用户密码以 bcrypt 哈希存储，状态文件不保存明文密码。
- 创建实例执行开机脚本、删机重建时生成的 SSH 私钥只在内存中使用，结束后即丢弃，不会写入磁盘。
- 开机脚本以 root 身份在新实例上执行，请只保存可信内容。
- 默认只监听 `127.0.0.1`，如需对外访问请自行用反向代理加 TLS。
## 开发

前端为 React + Vite（`frontend/`），使用 react-router 的多页面路由；构建产物输出到 `web/`，由 Go 通过 `//go:embed` 内嵌。

```bash
# 前端：安装依赖并构建（产物输出到 web/，供 Go 内嵌）
cd frontend && npm install && npm run build && cd ..

# 后端
go vet ./...
go test ./...
go build -o linode-panel .
```

前端开发时可启动 Vite 开发服务器（代理 `/api` 到 `127.0.0.1:8787`）：

```bash
cd frontend && npm run dev
```

后端使用 Go 标准库与 `modernc.org/sqlite`（纯 Go 的 SQLite 驱动，无需 CGO），可交叉编译为单二进制；前端资源已内嵌。

## 容器镜像与发布构建

仓库自带两个 GitHub Actions 工作流：

| 工作流 | 触发条件 | 产物 |
| --- | --- | --- |
| `.github/workflows/docker.yml` | push 到 `main`、推送 `v*` 标签、手动触发 | 面板镜像 `ghcr.io/<owner>/linode-panel`（linux/amd64 + arm64） |
| `.github/workflows/release.yml` | 推送 `v*` 标签 | `linode-panel` 与 `linode-panel-agent` 二进制压缩包（linux/darwin amd64+arm64、windows amd64），并附加到 GitHub Release |

镜像标签：分支名、`v*` 标签及其语义化版本（`1.2.3`、`1.2`）、commit sha；默认分支额外打 `latest`。

Release 工作流直接使用仓库中已提交的 `web/` 前端产物（由 `//go:embed` 打进二进制），不再在 CI 重复构建前端。**修改前端后请先在本地构建并提交 `web/`**，否则发布出的二进制会带旧 UI：

```bash
cd frontend && npm run build && cd ..
git add web && git commit -m "web: 重新构建前端产物"
```

Docker 工作流不受影响：镜像构建阶段仍会从 `frontend/` 重新构建前端。

面板容器（数据持久化在 `/data`）：

```bash
docker run -d --name linode-panel --restart unless-stopped \
  -p 8787:8787 \
  -v linode-panel-data:/data \
  ghcr.io/fearless743/linode-panel:latest
```

容器内默认监听 `0.0.0.0:8787`，数据库为 `/data/state.db`；首次启动请查看 `docker logs` 获取初始管理员密码。需要对外暴露时请在前面加反向代理并配置 TLS。

也可以直接用仓库自带的 `docker-compose.yml`：

```bash
docker compose up -d                 # 拉取 GHCR 镜像启动
docker compose up -d --build         # 或用本地 Dockerfile 构建后启动
docker compose logs -f               # 首次启动的管理员密码在日志里
docker compose pull && docker compose up -d   # 升级
```

默认同样只监听 `127.0.0.1:8787`，数据保存在命名卷 `linode-panel_panel-data`。可在同目录 `.env` 中覆盖以下变量：

```dotenv
PANEL_IMAGE=ghcr.io/fearless743/linode-panel:latest
PANEL_BIND=127.0.0.1
PANEL_PORT=8787
TZ=Asia/Shanghai
LINODE_API_BASE=https://api.linode.com/v4
# AUTO_REBUILD_CHECK_API=https://api.24kplus.com/ipcheck
```

### 一键安装（Linux + systemd）

`install.sh` 会从 GitHub Release 下载对应架构的二进制，创建独立系统用户和 systemd 服务，并把数据放在 `/var/lib/` 下。**需要仓库已发布过 `v*` 版本**（推送 tag 触发 `release.yml` 后才会有一键安装所需的产物）。

安装面板（默认监听 `127.0.0.1:8787`，可用 `--addr` 修改）：

```bash
curl -fsSL https://raw.githubusercontent.com/Fearless743/linode-panel/main/install.sh | sudo bash
```

安装远程 Agent（`--code` 只在首次注册时需要，token 保存后可从配置中移除）：

```bash
curl -fsSL https://raw.githubusercontent.com/Fearless743/linode-panel/main/install.sh \
  | sudo bash -s -- --agent --panel https://panel.example.com --code <注册码>
```

安装完成后：

```bash
systemctl status linode-panel          # 或 linode-panel-agent
journalctl -u linode-panel -f          # 面板日志（含首次启动的管理员密码）
```

重复执行脚本即可升级到最新 Release（数据与 `/etc/linode-panel/*.conf` 配置保留）；指定版本用 `--version v1.2.3`。脚本仅支持 Linux + systemd，其他系统请从 Release 手动下载二进制。

远程 Agent 不提供镜像，从 GitHub Release 下载对应平台的压缩包，解压后运行二进制即可（注册成功后 token 保存在本地状态文件，之后的启动可省略 `--code`）：

```bash
tar -xzf linode-panel_<版本>_linux_amd64.tar.gz
./linode-panel-agent --panel https://panel.example.com --code <注册码>
```

本地构建面板镜像：

```bash
docker build -t linode-panel .
```
